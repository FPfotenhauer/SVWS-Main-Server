# 1. Kontext

Der Schulträger-Server:

* Besteht aus Backend (Quarkus)
* Besteht aus Frontend (Vue SPA)
* Verwendet PostgreSQL
* Verwendet externen Identity Provider (z. B. Keycloak)
* Wird zunächst als MVP betrieben

Anforderungen:

* Containerisierte Auslieferung
* Einfache Installation
* HTTPS verpflichtend
* Geringer Betriebsaufwand
* Erweiterbar Richtung SaaS

Es muss entschieden werden:

> Wie wird das System im MVP bereitgestellt?

---

# 2. Entscheidung

Der Schulträger-Server wird im MVP betrieben als:

> Docker-basierte Container-Architektur
> mit Reverse Proxy (Nginx oder Traefik)
> und TLS-Termination

---

# 3. Architekturüberblick (Deployment)

```text
Internet
   ↓
Reverse Proxy (TLS)
   ↓
Frontend (Vue SPA)
   ↓
Backend (Quarkus API)
   ↓
PostgreSQL
```

Optional:

```text
Backend → Keycloak (OIDC)
Backend → Externe SVWS-Server
```

---

# 4. Containerstruktur (MVP)

## 4.1 Container

| Container           | Aufgabe                             |
| ------------------- | ----------------------------------- |
| reverse-proxy       | TLS, Routing                        |
| frontend            | Vue SPA (Node build → static files) |
| backend             | Quarkus Anwendung                   |
| database            | PostgreSQL                          |
| keycloak (optional) | Identity Provider                   |

---

## 4.2 Docker Compose (MVP)

Verwendung von:

```
docker-compose.yml
```

Ziel:

* Einfache lokale Installation
* Einfache Testumgebung
* MVP-Betrieb bei Pilotkunden

---

# 5. TLS-Strategie

TLS-Termination erfolgt im Reverse Proxy.

Optionen:

* Let’s Encrypt (automatisch)
* Kundenzertifikat

Backend läuft intern ohne TLS.

Warum?

* Vereinfachung
* Geringere Konfigurationskomplexität
* Standard in Container-Architekturen

---

# 6. Netzwerkarchitektur

Container-Netzwerk:

```
frontend → backend
backend → database
backend → keycloak
backend → externe SVWS
```

PostgreSQL ist:

* Nicht öffentlich erreichbar
* Nur im internen Docker-Netz

---

# 7. Konfigurationsstrategie

Konfiguration erfolgt über:

* Environment Variablen
* Keine festen Secrets im Image

Beispiel:

```
DB_HOST
DB_USER
DB_PASSWORD
OIDC_URL
OIDC_CLIENT_ID
OIDC_SECRET
```

---

# 8. Secret-Handling (MVP)

Im MVP:

* Docker-Environment-Variablen
* Keine Secrets im Git
* .env-Datei außerhalb Repository

Später:

* Docker Secrets
* Vault
* Kubernetes Secrets

---

# 9. Skalierungsstrategie (MVP)

Im MVP:

* Single-Instance Backend
* Single-Instance DB

Keine horizontale Skalierung.

Später möglich:

* Mehrere Backend-Instanzen
* Load Balancer
* DB-Replikation

Architektur bleibt stateless → skalierbar.

---

# 10. Deployment-Szenarien

## 10.1 Pilotbetrieb bei Schulträger

* On-Prem VM
* Docker Compose
* Reverse Proxy
* PostgreSQL lokal

---

## 10.2 Cloud-VM

* VPS
* Docker Compose
* Public DNS
* TLS via Let’s Encrypt

---

# 11. Backup-Strategie (MVP)

PostgreSQL:

* Regelmäßiger Dump
* Optional Cron-Job
* Volume-basiertes Backup

Noch keine:

* WAL-Replikation
* High Availability
* Failover-Cluster

---

# 12. Nicht implementiert im MVP

Bewusst nicht enthalten:

* ❌ Kubernetes
* ❌ Helm Charts
* ❌ Multi-Region Deployment
* ❌ Auto-Scaling
* ❌ Blue-Green Deployment
* ❌ Canary Releases

Begründung:

* MVP-Fokus
* Geringe Last
* Minimale Betriebsanforderungen

---

# 13. Sicherheitsmaßnahmen

| Maßnahme            | Umsetzung         |
| ------------------- | ----------------- |
| HTTPS               | Reverse Proxy     |
| DB Isolation        | Internes Netzwerk |
| Keine offenen Ports | Nur 80/443        |
| JWT Validierung     | Backend           |
| Mandanten-Isolation | Anwendungsebene   |

---

# 14. Logging-Integration

Container-Logs:

* STDOUT Logging (JSON)
* Docker Log Rotation
* Kein zentraler Log-Server im MVP

---

# 15. Qualitätsbewertung

| --------------- | --------- |
| Einfachheit     | Sehr hoch |

| Cloud-Fähigkeit | Hoch      |

---

# 16. Risiken

| Risiko                  | Gegenmaßnahme           |
| ----------------------- | ----------------------- |
| Single Point of Failure | Backup-Strategie        |
| Fehlkonfiguration TLS   | Dokumentation           |
| Secret Leakage          | .env nicht versionieren |
| Keine Hochverfügbarkeit | MVP-Phase               |
